# Security Policy & Architecture Safeguards — SlothSec

SlothSec is designed under strict application security principles to ensure that using a security maintenance platform never introduces security vulnerabilities or privacy risks into the user's environment.

---

## 1. Zero Cloud Egress & Privacy Sovereignty
- **All AI inference is 100% local:** Inference requests are addressed exclusively to `http://localhost:11434` (Ollama). Source code, findings, snippets, and filenames are never transmitted to cloud AI APIs (OpenAI, Anthropic, Hugging Face, etc.).
- **Local Persistence:** All finding data, scans, and patch history are stored strictly in a local SQLite file (`slothsec.db`).
- **Telemetry Isolation:** OpenTelemetry traces and metrics are retained in an in-memory ring buffer on the host machine. Sentry integration is disabled by default (`SENTRY_ENABLED=false`).

---

## 2. Multi-Tier Secret Redaction
Gitleaks detects credentials, API tokens, and private keys. To prevent secrets from leaking into logs, SQLite databases, reports, or LLM contexts:
1. Gitleaks is invoked with the `--redact` flag.
2. Parsed outputs pass through `redact_secrets()`, which employs regex patterns for GitHub tokens (`ghp_`), AWS Access Keys (`AKIA`), Bearer tokens, and private key blocks (`-----BEGIN RSA PRIVATE KEY-----`).
3. Matched tokens are replaced with `[REDACTED_SECRET]` before persistence or transmission.

---

## 3. Path Traversal & Symlink Escape Guards
All file paths originating from scanner outputs, API payloads, or patch requests are rigorously validated against the registered repository root:
```python
def validate_safe_subpath(repo_root: str, relative_or_absolute_file: str) -> str:
    root_resolved = Path(repo_root).resolve()
    target = Path(relative_or_absolute_file)
    if not target.is_absolute():
        target = root_resolved / target
    resolved_target = target.resolve()
    resolved_target.relative_to(root_resolved) # Raises ValueError if target escapes repo root
    return str(resolved_target)
```
Attempts to access `../` or escape via malicious symlinks trigger an immediate security exception.

---

## 4. Controlled Remediation & Execution Boundaries
- **No Automatic Code Mutation:** SlothSec strictly prohibits applying patches automatically. Human review (`Approve` action) is mandatory.
- **No Shell Command Execution:** SlothSec never executes shell commands generated by AI models.
- **Atomic Writes & Rollback:** Before modifying any file on disk, SlothSec creates a timestamped copy in `.slothsec_backups/` and uses atomic temporary file replacement (`os.replace`) to prevent file corruption.
- **Deterministic Verification:** A patch is only marked `VERIFIED_FIXED` when a subsequent real scanner execution proves the vulnerability is no longer detected.
